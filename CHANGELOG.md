### Unreleased

**New features**

- **The album-art render engines ported to Rust:** the album-art widget's pure render logic — the WCAG colour math behind the placeholder's note glyph, the half-block cell extraction behind every thumbnail render, and the two no-image row plans — now delegates to native engines when the Rust extension is built, with the pure-Python transcriptions kept in `ui/widgets/album_art.py` as the fallback for installs without it. The engines: `wcag_relative_luminance` (the relative luminance of a six-digit hex colour — the `strip()`/`lstrip("#")` normalisation with every leading hash stripped and the length counted in code points, then the sRGB linearisation `0.2126 R' + 0.7152 G' + 0.0722 B'` with the `c / 12.92` knee below 0.04045 and `((c + 0.055) / 1.055) ** 2.4` above it; the two-character channel pairs parse with CPython's own `int(s, 16)` acceptance — each pair stripped first, signs honoured so `-f` is channel −15, and with the per-pair strip the engine agrees with CPython on every two-character input, the `0x`-prefix and underscore forms `int()` additionally accepts being impossible in two characters and non-ASCII digits being base-10-only); `wcag_contrast_ratio` (`(lighter + 0.05) / (darker + 0.05)` through CPython's own two-argument `max`/`min`, so the NaN corners answer the reference's way); `wcag_readable_on` (the highest-contrast candidate pick — the first candidate kept whenever the background or any candidate is not a six-digit hex colour, and on ties, only a strictly greater ratio displacing the incumbent); `album_art_half_block_cells` (the per-cell top/bottom RGB pairs read row-major from the resized thumbnail's raw RGB buffer — `getpixel((x, y))` on an RGB-mode image is exactly `bytes[(y * width + x) * 3 : + 3]`, so the buffer walk and the old per-pixel walk agree cell for cell; a buffer whose length is not `width * height * 2 * 3` raises `ValueError` on both backends); `album_art_placeholder_rows` (the placeholder box's segment plan — the lower-half-block first row and upper-half-block last row checked in that order so a one-row box is all ▄ and a two-row box never shows a middle, the `height // 2` note row with `(width - 1) // 2` floor-division padding where width 0 pads −1 and reads as the empty string like Python's negative repeat); and `album_art_empty_rows` (the empty state's all-muted segment plan with the same middle-row geometry). The Pillow decode, the LANCZOS resize, the thumbnail download and the Rich `Text` assembly stay Python-side next to the I/O, and the module's LRU art cache keeps holding the assembled `Text` objects. `tests/test_ui/test_album_art_engine.py` pins the engines' contract on whichever backend is loaded (the luminance anchors and rejection set, the 21:1/1:1 ratio bounds, the first-wins tie rule, the row-major cell grid and the wrong-buffer refusals, the one-row/two-row/odd-width/width-zero row plans) and, when the extension is built, compares the native engines case-for-case against the pure-Python references run in a child interpreter with the import blocked — the ValueError refusals included — so the two implementations cannot drift; the `_image_to_half_blocks` refactor is pinned against the pre-engine `getpixel` walk kept in the test as an oracle, and the existing placeholder-contrast suite keeps exercising `_readable_on` on both backends.

- **The native crash-staleness version parser diverged from packaging 26.1's ASCII-scoped grammar:** `packaging` 26.1 wrapped its PEP 440 version-regex groups in `(?a:...)` scoping (and made the local alphabet ASCII), so the simple Unicode case folds the grammar admitted through 26.0 — the long s `ſ` (U+017F), the Kelvin sign `K` (U+212A), the dotted and dotless İ/ı (U+0130/U+0131) in local segments and in the `preview`/`post` marker words — are `InvalidVersion` from 26.1 on. The native engine carried the ≤ 26.0 grammar only, so on a fresh install (the `packaging>=21.0` dependency is uncapped; 26.1+ is what pip resolves today) the pure-Python fallback returned no verdict for `version: 1.0+ſ` while the native engine emitted the stale-build note — a native/fallback parity failure on the extension backend and wrongly-pinned tests on the fallback-only backend. The engine now carries both grammar shapes and takes an `admit_unicode_folds` flag; the Python binding probes the installed `packaging` once (`Version("1.0+ſ")` — parseable through 26.0, `InvalidVersion` from 26.1) and passes the verdict down, so the engine tracks the same reference the fallback itself calls on every release in the dependency range. The pinned fold tests now compute their expected verdicts from the installed `packaging` (the engine's actual contract), and new tests pin both grammar shapes directly — fold spellings parse and rank by raw characters with the flag on, are no-verdicts with it off, and every ASCII spelling gives the identical verdict either way.
- **The native crash-staleness version parser rejected Unicode fold characters packaging accepts:** the engine's PEP 440 grammar was written against a presumed `(?a:...)` ASCII scoping in `packaging`'s version regex that does not exist — `packaging` compiles its grammar with plain `re.IGNORECASE`, which on every supported CPython admits the simple case folds wherever a letter can appear: the long s `ſ` (U+017F) wherever an s/S can, the Kelvin sign `K` (U+212A) wherever a k/K can, and the dotted and dotless İ/ı (U+0130/U+0131) wherever an i/I can. So `1.0+ſ`, `1.0+K`, `1.0prevıew` and `1.0poſt` are valid versions on the fallback (on every `packaging` release in the supported range) but were rejected by the native engine — the divergence surfaced as a native/fallback parity failure and, on the fallback-only backend, as a test pinning the wrong behaviour. The grammar now admits the folds (only the `preview` word's i, the `post` word's s and the local alphabet can ever see one), and the pre/post/dev comparison slots were rebuilt onto packaging's own tuple semantics at the same time: each slot is the `(letter, number)` pair or the absent sentinel it is in `_cmpkey`, with the marker letter normalised through the lower+map step exactly like `_parse_letter_version` (`alpha`→`a`, `beta`→`b`, `c`/`pre`/`preview`→`rc`, `rev`/`r`→`post`) — a fold spelling that survives the lower() untouched (`prevıew`, `poſt`) compares as its raw string, ranking between `b` and `rc` and above `post`. The previous flat i8 rank also mis-ranked the normalised spellings (`alpha`/`beta` ranked with `rc` instead of `a`/`b`), which the tuple slots now fix.
- **The native formatting functions were never actually used:** the `if _HAVE_NATIVE:` bindings in `utils/formatting.py` were assigned *before* the pure-Python `def` statements, which immediately clobbered them — `format_duration`, `truncate`, `normalize_tracks` and ten others always ran the Python fallback even with the extension compiled. The native overrides are now bound at the end of the module (the same pattern `bidi.py` uses), so they take effect for real.
- **`normalise_region`'s native path could never load:** `services/regions.py` imported the extension with a `.` relative import, but the module lives in the `utils` package — the import always failed and the pure-Python fallback always ran. Fixed to import from `..utils`.
- **Native divergences from the Python reference**, exposed by the fixes above and now corrected: `build_playlist_subtitle` didn't lowercase the privacy label (`PUBLIC` → `PUBLIC` instead of `Public`); `normalize_tracks` replaced the `artists` entries with plain name strings instead of preserving the original dicts (breaking artist navigation); `sanitize_title_for_lyric_lookup`'s regex missed case variants like `(Official Video)`; `extract_duration` mis-parsed string `duration_seconds` values; and the artist-prefix strip could slice a multi-byte character.
- **`format_ago` crashed on naive datetimes without the native extension:** the pure-Python fallback subtracted an offset-naive timestamp from an offset-aware "now", raising `TypeError`. Naive timestamps are now interpreted as UTC on both the native and fallback paths.
- **Lint and type-check drift from the earlier porting commits:** import blocks that `ruff==0.15.1` (the pinned CI version) rejects, an unused import in `test_transliteration.py`, sixteen `reportPossiblyUnboundVariable` errors from native symbols guarded by a flag pyright cannot narrow, and a yt-dlp stub mismatch in `auth.py`. All resolved; `ruff format`, `ruff check`, and `pyright` now pass clean.
- **Duration column cut off again once a track list needs scrolling** — the Title column is sized from the table's width before the layout has settled, so the fit misses the row-label gutter, the width Artist and Album grow into, and the vertical scrollbar that appears as soon as the list is longer than the window. The table came out wider than its viewport, scrolled sideways, and pushed the rightmost column off the right edge — the same symptom the v1.9.2 fix addressed. The fit now runs once more after the layout settles, including when rows are appended to a table that has already been painted.
- **Choosing an action with Enter no longer replaces the queue**: picking Play Next, Add to Queue or Go to Artist from the track actions menu with the keyboard also played the row the menu was opened on, replacing the queue with the page's list. The menu now consumes the Enter that picks the action, so the keyboard does exactly what a mouse click does. Thanks for the report @tmbrid (#177).
- **Tracks skipped with `HTTP error 403 Forbidden` on yt-dlp 2026.10.21 or newer**: that release made `tv_samsung` one of yt-dlp's default YouTube clients. On a free account, its stream for a track with a pre-roll ad stays locked until the ad would have finished, and yt-dlp marks that moment as `available_at`. yt-dlp's own downloader waits for it, but ytm handed the URL to mpv straight away, so the open hit 403, the one-time retry got a fresh ad timer and failed the same way, and the track was skipped. Playback now waits until the stream is available, which delays the start of that track by up to the length of the ad. A prefetched next track usually has no wait left. Thanks to @tmbrid for the report, @ardzz for the fix and @slastra for the diagnosis (#195, #190).

- **Config resilience** — a corrupt `keymap.toml` is backed up and replaced with defaults instead of aborting startup, settings values are type-validated at load, and `cache_dir` accepts `~` paths.
- **Navigation state stays fresh** — pages no longer restore stale cursor/content state, and deleting a playlist purges its cached pages instead of leaving ghost entries reachable via Back.
- **Popup backdrop clicks** — clicking outside any popup now dismisses it consistently, across all popups.
- **Database errors degrade gracefully** — SQLite errors at history/session write sites are caught alongside OS errors instead of crashing the operation.
- **Player teardown races** — transport actions during mpv shutdown no longer raise, and a failed stream start no longer disturbs end-of-track handling for the track after it.
- **Media-key presses can no longer vanish** — Windows and macOS key callbacks were scheduled without holding a reference, so the garbage collector could occasionally reclaim one mid-flight and the press did nothing. A shared dispatcher now keeps every in-flight callback alive.
- **Radio respects shuffle from a cold start** — starting radio into an empty queue with shuffle on skipped the shuffle-order build, so tracks played in linear order until shuffle was toggled off and on.
- **Fast track-switching can't wedge stream resolution** — cancelling a track that was still resolving could leave the next request for the same track waiting forever, or turn a successful resolve into an error. Both cancellation paths now settle cleanly.
- **Playlist-creation failures say why** — creating a playlist (sidebar, picker, or Spotify import) now reports whether it failed from an expired session, a network problem, or a server error, instead of a generic "Failed to create playlist".
- **A corrupt saved volume can't derail startup** — a garbage `volume` in session.json falls back to the default and out-of-range values clamp to 0–100, instead of aborting the session restore midway.
- **Liked Songs distinguishes "empty" from "failed"** — a fetch failure now shows a check-the-log message instead of the misleading "No liked songs found."
- **Browse outages say so** — when For You or Charts can't be fetched (network, expired session, server error), the sections now show the retryable error copy instead of pretending the account has no recommendations or the region has no charts.
- **Two swallowed-input quirks** — a right-click that didn't open a popup no longer eats your next Enter/click, and picking a search suggestion identical to the current input no longer eats the next keystroke.
- **`ytm doctor` stops counting bystanders** — any process whose command line contained a `/ytm…` path (an editor open on the repo, say) counted as a running instance; only the real `ytm` / `python -m ytm_player` entry points match now, including console-script launches (where the interpreter sits in argv[0] and the `ytm` script path in argv[1]).
- **A crashed session can't lock you out** — if the OS handed a crashed instance's PID to an unrelated process, `ytm` refused to launch until `ytm.pid` was deleted by hand; the single-instance guard now checks that the recorded process is actually ytm-player and cleans the stale file itself.
- **Parser drift isn't blamed on your connection** — when YouTube changes a response shape mid-operation, the error now reads as a server problem instead of "check your internet connection".
- **No phantom crash file from the yt-dlp pre-warm** — a failure in the background yt-dlp import was written out as a crash file; it now logs a warning, and the only real cost is a slower first play.

**Internal**

- The five per-page track-filter stacks are unified into one shared mixin, all popups sit on a shared base shell, and the ytmusicapi sort-parameter patch window no longer leaks into unrelated concurrent API calls.
- First dedicated test coverage for the Spotify import service and the mpv player wrapper.
- Services dedup sweep: the Python 3.10 StrEnum shim has one home, the three platform media-key services share one thread→loop dispatcher, stream-URL expiry follows a single policy, the lyrics and update-check fetchers use `requests`, and duplicated CLI/IPC boilerplate, path normalizers, listen-logging, and go-to-artist/album id extraction each collapsed into single implementations. Page-load failures now log their real tracebacks.
- Packaging hardening: the AUR package now declares `python-packaging`, requires `dbus-fast` 5.x (4.x is the #113 crash combo), and caps textual below 9.0; a mistagged release can no longer upload the wrong version to PyPI (the tag is checked against `__version__` before anything builds); CI now also runs on pull requests targeting `dev`.

**Fixes — concurrency / stability**

- Player no longer races on track changes — `_current_track` writes during `play()` and `stop()` are now under `_skip_lock`, preventing torn reads from MPRIS, Discord, Last.fm, and the end-of-track callback during rapid skips (C1).
- mpv crash recovery no longer silently breaks subsequent playback — when `_play_sync` catches `mpv.ShutdownError` and `_try_recover` succeeds, `_current_track` and the `TRACK_CHANGE` event payload now stay consistent. (Two issues here: an initial fix went too far and cleared `_current_track` mid-`play()`, breaking MPRIS/Discord/Last.fm and stopping auto-advance after recovery — caught in final review and reverted.)
- `ytmusic.get_playlist(order=...)` is now safe under concurrent calls — the function monkey-patches ytmusicapi's internal `_send_request` to inject the `order` parameter, but two concurrent calls would corrupt the patch state. Now serialized with an `asyncio.Lock` (C3).
- Settings.toml and session.json writes are now atomic — uses `os.replace` after writing to a `.tmp` sibling, so power loss / `kill -9` mid-write can no longer leave you with a half-written file that crashes startup.
- Session.json corruption no longer crashes startup — bad JSON or schema mismatch falls back to defaults silently. First launch (file absent) stays silent; format mismatch on existing files logs a warning.
- Play failures no longer block retry within 1 second — the double-click debounce stamp now clears on stream-resolution failure or `player.play()` exception, so clicking the same track again after a failure isn't silently swallowed.
- Update check no longer pins users to a stale "latest" if the system clock ever ran fast — negative cache age now triggers a re-fetch.
- Bare `except:` swallows promoted to `logger.exception` in 6 high-impact spots (player callbacks, ytmusic API failures, MPRIS/Discord/Last.fm errors, history logging) — failures that previously vanished now show up in `~/.config/ytm-player/logs/ytm.log` with a stack trace.

**Performance**

- Theme switches feel instant — `theme.toml` is now mtime-cached in `get_css_variables` instead of being parsed from disk on every CSS variable lookup. Edits to `theme.toml` still pick up automatically (mtime invalidates the cache).
- Queue page play-indicator update is O(1) instead of O(n) — switching tracks no longer rewrites every row in queues with hundreds of tracks; only the changed cells are touched.
- Album art rendering moved off the event loop — `_image_to_half_blocks` (PIL resize + per-pixel iteration) now runs in `asyncio.to_thread`, so loading a thumbnail never blocks input handling.
- Library page background workers cancel on page removal — the "fetch remaining tracks" worker for large libraries no longer keeps running after you've navigated away.
